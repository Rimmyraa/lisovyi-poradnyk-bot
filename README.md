# 🌲 Лісовий порадник

Telegram-бот для звірів лісу. Він відповідає на питання за документами з «Лісового архіву» та за документами, які звірі надсилають йому в Telegram. До кожної поради бот каже, з якого вона документа, а для документа з Telegram ще й хто і коли його надіслав.

Тестове завдання для замовниці Мишки-шкряботушки. LLM: Groq (безкоштовний рівень).

## Запуск

```bash
cp .env.example .env      # впишіть TELEGRAM_BOT_TOKEN і GROQ_API_KEY
docker compose up -d --build
```

Перший запуск триває 1–3 хвилини: бот читає 78 документів архіву і розпізнає скановані PDF (OCR). Далі все береться з бази в томі `bot-data` і переживає перезапуски.

Логи: `docker compose logs -f bot`.

## Вимоги, з'ясовані в розмові з Мишкою

| # | Вимога | Як зроблено |
|---|---|---|
| 1 | Звірі питають бота й отримують відповіді з документів, які надіслали інші звірі | Пошук фрагментів за місцем + BM25, відповідь генерує LLM лише з цих фрагментів |
| 2 | Бот **завжди** каже, яку пораду взяв і з якого документа | Після кожної поради стоїть посилання `[n]`, внизу список «📄 Джерела». Список формує код, а не LLM, тож назви й дати не вигадуються |
| 3 | Для документа з Telegram треба казати, **хто надіслав і коли** | Зберігаються ім'я/@username і час повідомлення (за Києвом) |
| 4 | Частина документів лежить у теці «Лісовий архів» на Google Диску | Копія архіву в `data/archive` завантажується при старті. Можна брати теку прямо з Диска (`GDRIVE_FOLDER_ID` + `GOOGLE_API_KEY`) |
| 5 | Нові поради звірі надсилають боту документами: PDF, Word або текст, **не фото** | Приймаються `.pdf`, `.docx`, `.txt`. На фото й інші формати бот ввічливо пояснює, що треба |
| 6 | Поради бувають для всього лісу, для частини лісу або для конкретної рукавички; звір сам каже в питанні, про яке місце питає | Кожен документ має область дії; питання розбирається на місця |
| 7 | Відповідність рукавичок частинам лісу вже відома («Карта лісу») | Бот читає легенду з документа «Карта лісу» при старті. Для рукавички беруться поради самої рукавички, її частин лісу і всього лісу. «Під вербою» — і листяний ліс, і річка; «На узліссі» — жодна частина |
| 8 | Якщо з тексту зрозуміло, для кого порада, бот визначає сам; якщо ні, **перепитує відправника, а не вгадує** | Правила (назва, вступ «для всіх мешканців лісу» тощо) → підпис до файлу → LLM, яка має навести цитату-доказ. Немає доказу — кнопки з місцями відправнику, документ чекає відповіді |
| 9 | За сезон назбирається кілька сотень документів; бот має їх **запам'ятовувати** (у теку на Диску зберігати не треба) | SQLite у Docker-томі. У LLM потрапляють лише релевантні фрагменти, тож обсяг не впирається в ліміти Groq |
| 10 | Надсилати документи може будь-який звір, усі рівні, адмінів немає; надсилають в особисті | Без ролей і обмежень. Бот працює лише в особистих чатах |
| 11 | Якщо поради різняться, перевага за **конкретнішою**: спершу для рукавички, потім для частини лісу, а вже тоді загальна | Правило в інструкції для LLM. Бот дає лише пораду-переможницю. Приклад з архіву: для рукавички в хвойному лісі «утеплювати в жовтні», а не в листопаді, як у загальному «Календарі сезонів» |
| 12 | **Новіша версія того самого документа для того самого місця замінює стару**, звірі бачать лише чинну пораду | Та сама назва (без урахування регістру, «(1)», «v2») + той самий набір місць → стара версія позначається заміненою і зникає з пошуку. Відправник бачить, що саме замінено. Повторно надіслана стара версія не повертається |

### Рішення, які Мишка залишила на мене

- **Питання без місця.** Бот відповідає за порадами для всього лісу (пожежа, мисливці, отруйні гриби) і пропонує уточнити рукавичку. Якщо відповідь залежить від місця (внески, чергування), бот питає «Про яку рукавичку?» кнопками і відповідає після вибору.
- **Продовження розмови.** «А хто там чергує?» після питання про «Під дубом» стосується того самого місця (протягом 30 хвилин).
- **Дублікати.** Повторно надісланий той самий файл не дублюється.
- **Невідоме місце.** Якщо звір питає про місце, якого немає на карті, бот перелічує відомі.

## Що знайшлося в архіві

- 78 документів: 38 PDF, 19 DOCX, 21 TXT.
- **19 PDF — скани без текстового шару.** Бот розпізнає їх через Tesseract (українська) з очищенням фону-«берести».
- Область дії кожного архівного документа визначається автоматично, без LLM: 7 для всього лісу, по 5 для кожної частини лісу, по 7 для кожної з 8 рукавичок.

## Як це працює

```
Документ ─► витяг тексту (pdftotext / python-docx / OCR) ─► область дії ─► SQLite
                                                              │ (незрозуміло → перепитати відправника)
Питання ─► розбір місць (LLM, швидка модель) ─► області за картою ─► BM25 по фрагментах цих областей
       ─► відповідь LLM лише з фрагментів, з [n] ─► код додає список джерел (назва, область, хто/коли)
```

- `bot/extract.py` — текст із PDF/DOCX/TXT, OCR сканів.
- `bot/forest_map.py` — рукавички, частини лісу, читання «Карти лісу».
- `bot/classify.py` — для кого документ (правила → LLM з цитатою-доказом).
- `bot/search.py` — пошук (BM25 з простим стемінгом для української).
- `bot/qa.py` — відповіді, пріоритети, джерела.
- `bot/llm.py` — Groq через OpenAI-сумісний API, автоматичний перехід на запасну модель при ліміті (429) або вимкненій моделі.
- `bot/handlers.py` — Telegram (aiogram 3), кнопки вибору місця.

## Команди бота

- `/start`, `/help` — що вміє бот і приклади питань.
- `/places` — рукавички і частини лісу.

## Тести

```bash
pip install -r requirements.txt pytest
python -m pytest     # потрібні tesseract-ocr-ukr і poppler-utils
```

Тести працюють на справжньому архіві з підставною LLM. Вони перевіряють OCR, області всіх 78 документів, карту, фільтрацію за місцем (зокрема «На узліссі»), перепитування відправника, підпис до файлу, дублікати, заміну старих версій, уточнення місця в питанні, продовження розмови і перенумерацію джерел.
